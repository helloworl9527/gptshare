# 有空位但无法兑换的排查与提示

账号的 `最大并发数 - 当前占用数` 是物理空位，不一定是可兑换容量。选号还要求账号未归档、状态为 `available`、订阅未过期、未被监控判定封禁。仪表盘 `available_capacity` 与选号共用条件；`blocked_capacity` 单独统计有空位却不能兑换的账号及原因。

监控的 `alive` 是最近一次检测状态，不代表当前订阅仍有效；授权撤销后暂停轮询的账号可能长时间保留旧状态和到期时间。不能通过删除订阅时间校验、增加并发上限或伪造到期时间来恢复库存。需补充有效账号，或重新授权并确认续订时间后同步。

本次修复：

- 用户兑换接口返回 `no_account_capacity` 时，直接显示“暂无可分配账号，兑换未完成，卡密未消耗”，不再继续查询未激活的卡密，避免覆盖真实错误及累积无意义的查询验证码失败次数。
- 新查询开始时隐藏上一次账号结果并停止旧凭据倒计时，避免失败后误以为已分配旧账号。
- 后台账号池逐行显示真正可兑换的位数；即使旧状态为 `available` 且监控为 `alive`，订阅到期后仍标为“订阅已过期，空位不可兑换”。到期判断每秒更新。
- 监控状态同步以分配域的订阅时间为边界，不能把旧的 `alive` 当成仍可分配的依据；已下线或已封禁账号不因普通同步重新开放。

容量不足时兑换事务回滚：卡密保持未使用，不开始计时，不新增分配，不修改现有用户占用。修复不改变选号条件或增加账号容量，也不自动兑换生产卡密。

回归覆盖订阅到期边界、状态同步、4 个受阻空位、兑换回滚、重复失败不触发查询验证码，以及补充模拟库存后的成功流程（桌面和移动端）。

## 过期账号未自动下线

自动归档要求账号已过期或已封禁，并且没有任何活跃分配。不能在仍有主分配用户未迁走时清除账号凭据。

定时扫描此前把“已经过期”的换号也归为 `account_expiring`，导致迁移后仍生成 24 小时宽限期，旧账号被活跃 `grace` 记录阻止归档。现已按订阅到期时间及终止状态区分 `account_expired`，迁移成功后直接关闭旧分配，不新建宽限。已有挂在过期账号上的宽限记录在扫描中结算，再执行归档；新账号上的有效主分配不受影响。未到期账号正常的换号宽限期仍保留。

如果备用容量不足，过期账号的尚未迁移主分配继续保留，账号状态标为 `expired` 而不是 `available`；空位不能用于兑换。该保护不会伪造订阅有效期，也不会作废仍有效的用户卡密。
