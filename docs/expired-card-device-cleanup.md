# 仪表盘过期卡密清单

运营总览底部的“近 3 天已过期卡密及对应账号”用于人工清理账号登录设备。每张卡密展示尾号、编号、到期时间及所有曾分配过的账号，包括换号前的账号和已下线账号；同一账号多次分配会合并并显示最近一次分配时间。

清单依据服务器当前时间，只显示到期时间位于 `[当前时间 - 72 小时, 当前时间]` 的卡密，两端均包含，包含尚未被每小时扫描更新状态的已到期 `redeemed` 卡密。超过 72 小时前已过期、尚未到期、未激活、已作废和已延期恢复有效期的卡密不显示。总数、搜索及分页均使用这一时间范围。刷新清单或运营总览可重新读取数据。

账号的“当前有效卡密”从实际分配记录统计，包含尚在宽限期内的有效分配，不依赖可能滞后的容量计数。仍有有效卡密的账号需要保留正常用户的设备。该页面不读取设备会话，也不执行登出操作；分配历史本身无法确定某个设备属于哪张卡密。

管理员只读接口：`GET /api/admin/dashboard/expired-cards`。需要管理员会话，响应设置 `Cache-Control: no-store`。

- `page`：从 1 开始，默认 1，上限 1000000。
- `page_size`：默认 20，允许 1–100，按卡密分页，同一卡密的账号不会分散到不同页。
- `search`：最长 256 字符，按账号邮箱、卡密尾号模糊查找，或按卡密编号精确查找。匹配某个账号后仍返回该卡密的全部历史账号。
- 响应包含 `cards`、`total`、`page`、`page_size`、`request_id`；`cards[].accounts` 包含账号编号、邮箱、状态、下线标记、最近分配时间和有效卡密数。不返回完整卡密、密码、2FA 或监控凭据。

查询只使用分配数据库，读取同一事务快照，不修改过期状态、分配记录或容量，也不需要数据库迁移。
