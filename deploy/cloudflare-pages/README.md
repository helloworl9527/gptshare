# ShareGPT user frontend on Baochai Pages

The `/sharegpt/` child page uses the existing `web/public/user.html` and static assets. Only five user JSON POST endpoints are proxied to `https://gpt.baochai.cc`: redeem, card query, card-action preview, renewal, and different-account redemption. Admin APIs, cookies, authorization headers, redirects and query-string card codes are not forwarded. Captcha and backend response status are preserved. Account responses are never cached.

The build downloads publicly served navigation/recharge assets, keeps an original public snapshot, adds one navigation entry and retains the `REDEEM_PROXY` service binding for the existing `/ios/api/` and `/lz/api/` routes. It does not download Worker source or export Cloudflare secrets. Card-action state lives in the allocation backend, never in Pages.

The ShareGPT FAQ is defined in `web/public/user.html`, with scoped styles in `web/public/static/user.css`. Its timezone tutorial image is the user-supplied `web/public/static/change-timezone-ip-settings.jpg`; the build includes it as `image/jpeg` and the Worker explicitly allowlists its exact path. Keep the build entry and Worker allowlist in sync when adding assets. The FAQ contains the site owner's requested timezone notice, extension link, setup steps and tutorial image. It uses native `<details>` and needs no new script or third-party image request. Run `npm run smoke:faq` for a local Worker-backed browser check, or pass an explicit HTTPS ShareGPT URL after a deployment.

Run `npm ci`, `npm test`, then `npm run build -- /absolute/ignored/artifact-directory`. Requires Node.js 20+ with network access. Artifacts default to `.workflow/artifacts/cloudflare-pages` (git-ignored). Public upstream resources must all be available; build aborts on missing files or unexpected layout. With the project's `web` browser-test dependencies installed, run `npm run smoke -- https://preview-host` to verify navigation, simulated captcha/account results and the two original recharge providers. No real card is submitted by this test.

Upload assets using Cloudflare Pages' short-lived upload token, BLAKE3 manifest and multipart deployment API. Upload tokens must stay in memory and must never be logged. Deploy a preview branch first, check static resources and both existing recharge provider APIs, then create an identical production deployment on `main`. Preserve the previous production deployment ID for rollback. Existing project bindings and compatibility settings must be retained.

Browser history of previously redeemed cards remains scoped to the original site's origin; it is not migrated between the server and Pages domain. Do not enter real card codes into automated deployment checks.

Schema 18 must be deployed in the backend before enabling the new Pages UI. Roll back Pages using its saved previous deployment ID. Once renewals have committed, do not restore the pre-migration database or run an older backend: it would lose paid transactions or reject `consumed` cards. Keep the schema-18 backend and set `PUBLIC_CARD_ACTIONS_ENABLED=false` to disable these three new endpoints while leaving ordinary queries available.
